# AI Usage Policy

AI tools, including large language models and other probabilistic assistants, may be used when contributing to the project. This covers code, documentation, pull requests, issues, comments, and any other contribution.

Use is allowed only when the contributor stays fully in charge of the result. Every AI-assisted change must be read, checked, and supervised by the person who submits it. The contributor must understand the contribution, be able to explain it, and stand behind it. Output that has not been reviewed does not meet this policy.

We still take a cautious approach to these tools because of their effects, both unknown and observed, on project health and maintenance burden. The conditions below exist for that reason. This field is evolving quickly, so we may revise this policy later. Our rationale is as follows:

**Maintainer burden:** Reviewers depend on contributors to write and test their work before submitting it. These tools make it easy to generate large amounts of plausible-looking text and code that the contributor does not understand, has not tested, and cannot defend. That is a drain on reviewer time. AI assistance is acceptable when the contributor has already done that review.

**Correctness and security:** Even when code generated by AI tools seems to function, there is no guarantee that it is correct, and no indication of what security implications it may have. A web browser engine is built to run in hostile execution environments, so all code must take potential security issues into account. The contributor, not the tool, is responsible for that judgment.

**Readability:** AI-assisted code must stay clear and proportionate to the change. Heavy, opaque, or unnecessarily verbose code is not acceptable, even when it appears to work. Prefer the smallest change that a reviewer can follow.

**Copyright issues:** Publicly available models are trained on copyrighted content, both accidentally and intentionally, and their output can include that content verbatim. Since the legality of this is uncertain, contributors must review generated output for material they cannot account for, and must not submit work that would violate the licenses of copyrighted works.

**Ethical issues:** AI tools require an unreasonable amount of energy and water to build and operate, their models are built with heavily exploited workers in unacceptable working conditions, and they are being used to undermine labor and justify layoffs. These are harms we do not want to perpetuate. Use these tools deliberately, and only where a person will still review and own the result.

<div class="warning">

AI tools can sometimes answer questions you may have about the project, but we’ve found that these answers are often incorrect or very misleading.

In general, do not assume that AI tools are a source of truth regarding how the engine works. Consider asking your questions [on Github discussions](https://github.com/aetherbrowser/aether/discussions) instead.

</div>

### AI Policy FAQ

#### Can I use AI tools to help translate from my native language to English?

Yes. Read the result and correct anything that does not say what you meant.

#### Can I use an AI tool to assist in finding bugs or security issues?

Yes, but you must verify the output before filing issues against the project.
You must be able to reproduce and validate any findings. Do not file a report that only restates the tool’s output.

#### Can I use an AI tool to help me understand the codebase better?

Yes, but see the earlier warning about these tools’ reliability. Treat the answer as a starting point and check it in the code.

#### Can I use AI to help write code?

Yes, if you fully supervise the result.

You must read the code, understand it, test it, and be able to discuss it in review. You are responsible for its correctness, security, and fit with the surrounding code. Do not submit code you have not controlled.

The code must stay readable. Do not land large, heavy, or opaque generated changes. If the tool produces more code than the problem needs, cut it back before opening a pull request.

#### Can I use an AI tool to write documentation, a pull request description, an issue, or a comment?

Yes. A careful reread is required.

Check that the text is accurate, specific, and in your own voice. Remove filler, unsupported claims, and anything you cannot verify. A description that you have not reviewed does not meet this policy. For pull requests, also follow the [project best practices](../contributing/making-a-pull-request.md#title-and-description).

#### Can I use an AI review tool on my pull request?

Yes, as a supplement to your own review. Read the comments, drop the ones that are wrong or noisy, and do not treat the tool as a reviewer. Maintainers still expect you to have supervised the change yourself.

#### What happens if a contribution does not meet this policy?

Maintainers may ask you to rework a pull request, or close it, when the code looks unsupervised, untested, heavy, or unreadable, or when you cannot explain it.

The same applies to documentation, pull request text, issues, and comments that have not been carefully reviewed: they must be rewritten until a person has checked them and can stand behind them.
